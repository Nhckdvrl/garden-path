# CK-P1 Design Audit — Publicness vs Finite Recursive Knowledge

**Created:** 2026-09-06  
**Authority:** MAINLINE_AUDIT_2026-09-06_V9.md  
**Status:** editable pre-freeze design. **Not yet preregistered. No target-model generation yet.**

This file exists to prevent the authorized small pilot from becoming another
overconstructed experiment.

The question is simple:

> **When the same first-order fact is known by both people, does jointly observable
> public acquisition change recursive-knowledge behavior in a way that finite
> privately communicated nesting does not?**

The pilot searches for a new LLM-specific law. It does not assume one exists.

---

## 1. Non-negotiable design constraints

A CK-P1 sample must be understandable without:
- the terms common knowledge, mutual knowledge, epistemic logic, Kripke model,
  public-announcement logic, or recursive closure;
- metadata fields shown to the model;
- an invented protocol;
- a game;
- a legal or institutional procedure;
- an LLM judge.

Each scenario should read like an ordinary miniature story.

Maximum visible structure:
- two people;
- one arbitrary fact P;
- one information-acquisition episode;
- one TRUE/FALSE query.

If a sample needs a paragraph explaining its epistemic semantics, delete it.

---

## 2. One matched quartet

The same proposition is used in all four conditions.

Example proposition:

> The workshop starts at 3:00.

### K1 — private duplicated

Alice receives a private message telling her that the workshop starts at 3:00.

Separately, Bob receives a private message telling him that the workshop starts at
3:00.

Alice is not shown Bob's message, and Bob is not shown Alice's message.

### K2 — reciprocal finite

Alice privately receives two pieces of information:
- the workshop starts at 3:00;
- Bob knows that the workshop starts at 3:00.

Bob privately receives two pieces of information:
- the workshop starts at 3:00;
- Alice knows that the workshop starts at 3:00.

They do not see each other's private messages.

### K3 — doubly reciprocal finite

Alice privately receives:
- the workshop starts at 3:00;
- Bob knows that it starts at 3:00;
- Bob knows that Alice knows that it starts at 3:00.

Bob privately receives:
- the workshop starts at 3:00;
- Alice knows that it starts at 3:00;
- Alice knows that Bob knows that it starts at 3:00.

They do not see each other's private messages.

### CK — jointly observable

Alice and Bob are standing together when the organizer says:

> "The workshop starts at 3:00."

Both hear the organizer clearly, and each can see that the other is present and
listening to the same announcement.

No line says that the fact is "common knowledge."

---

## 3. Query family

Queries are issued independently.

For an Alice-outer chain:

- d1: Alice knows that the workshop starts at 3:00.
- d2: Alice knows that Bob knows that the workshop starts at 3:00.
- d3: Alice knows that Bob knows that Alice knows that the workshop starts at 3:00.
- d4: Alice knows that Bob knows that Alice knows that Bob knows that the workshop
  starts at 3:00.
- d6: continue the same alternating pattern to six knowledge operators.

Half the skeletons should use Bob as the outermost holder.

Answer format:
TRUE
or
FALSE

No explanation requested in the primary run.

---

## 4. Gold

| structure | d1 | d2 | d3 | d4 | d6 |
|---|---:|---:|---:|---:|---:|
| K1 | TRUE | FALSE | FALSE | FALSE | FALSE |
| K2 | TRUE | TRUE | FALSE | FALSE | FALSE |
| K3 | TRUE | TRUE | TRUE | FALSE | FALSE |
| CK | TRUE | TRUE | TRUE | TRUE | TRUE |

The finite conditions deliberately create a staircase.

The CK condition is not generated by adding a sentence saying all nested beliefs are
true. Its deeper gold follows from the jointly observable public event under the
idealized assumptions stated in the story.

---

## 5. Qualification probe

One direct structural probe per context:

> Did Alice and Bob jointly witness the information in a way that each could observe
> the other's access to it?

Gold:
- K1 FALSE
- K2 FALSE
- K3 FALSE
- CK TRUE

Purpose:
detect whether a later deep-closure error is merely a first-order failure to parse the
information structure.

This probe is supporting only.

Do not create ten separate access probes.

---

## 6. Skeleton budget

Target: **24 independent semantic skeletons**.

The skeleton is the proposition/content frame, not a name substitution.

Suggested shallow domains:
1. meeting / event time;
2. room or desk assignment;
3. package / object location;
4. simple object property;
5. event date;
6. schedule / destination.

Four genuinely different base propositions per domain is sufficient.

Avoid:
- famous facts;
- real current events;
- emotionally charged content;
- safety-sensitive decisions;
- moral dilemmas;
- legal cases;
- beliefs with presupposition or ambiguity;
- facts whose truth is inferable from world knowledge.

The information structure, not P's semantics, is the research variable.

---

## 7. Publicness cue diversity

The initial 24 skeletons should not all use one lexical frame.

Use a small number of ordinary jointly observable realizations, for example:
- live spoken announcement while both are visibly present;
- both look at the same newly displayed notice while standing together;
- both watch the same simple demonstration and can see the other watching.

The underlying epistemic requirement is:
each has access to P and access to the other's access.

Do not use the literal adjective "public" as the only cue.

Do not add a dozen cue types.

Pilot requirement: at least two cue families must contribute to any effect before it
is considered robust enough for a second audit.

---

## 8. Matching constraints

Within a matched quartet:
- P must be byte-identical;
- names must be identical;
- outer query holder must be identical;
- query text must be identical;
- only the information-acquisition structure changes.

Do not chase exact token-count matching if it makes the stories unnatural.

Length is recorded and can be checked descriptively.

If a result is entirely predicted by length, kill it.

---

## 9. What NOT to add to P1

Do not add:
- hidden observers;
- unreliable speakers;
- partial hearing;
- deceptive announcements;
- group sizes >2;
- multi-turn dialogue;
- coordination games;
- memory delays;
- chain-of-thought conditions;
- model self-reports about its strategy;
- mechanism probes;
- system-vs-user role manipulations;
- explicit definitions of common knowledge.

Those are possible later discriminators only if a simple phenomenon first exists.

---

## 10. Model panel

Three families only.

Freeze exact checkpoints before output:
- one strong Qwen3.5-class model;
- one Gemma-3-class model;
- one Mistral-Small-class model.

No small-model-centered story.

No scale sweep in discovery.

Temperature 0 / deterministic decoding if supported.

Primary answer budget should be minimal because output is TRUE/FALSE.

---

## 11. Analysis plan

Unit of independence: semantic skeleton.

Never treat the five depths or four structures from one skeleton as independent
items for uncertainty estimation.

Report per model:
- accuracy by structure × depth;
- TRUE rate by structure × depth;
- qualification accuracy;
- finite-boundary accuracy for K1/K2/K3;
- deep CK accuracy for d4/d6.

Use cluster bootstrap over the 24 skeletons for contrasts.

Possible descriptive contrasts:
- deep CK vs K3 beyond-boundary TRUE-rate difference;
- public depth slope vs finite depth slope;
- excess TRUE beyond the licensed K1/K2/K3 boundary.

These are descriptive discovery quantities until a post-P1 audit selects a real law.

No new composite ratio.

---

## 12. Pre-output checks

Before any target output:
- every scenario manually/readability audited;
- exact gold generated;
- gold table unit-tested;
- no sample contains forbidden technical vocabulary;
- matched quartet keeps P and query invariant;
- no accidental statement in K1/K2/K3 reveals a deeper level than intended;
- no CK item explicitly spells out recursive closure;
- parser accepts only TRUE/FALSE;
- semantic skeleton ID is stored for cluster analysis;
- exact prompts are frozen.

---

## 13. Post-output kill rules

Kill the candidate if:
- structural qualification is poor;
- all errors are generic nesting-depth errors;
- CK has no publicness-specific behavior;
- K1/K2/K3 simply show the already-known private/mutual confusion with no deeper
  closure structure;
- only one model family produces an effect;
- cue-family decomposition contradicts the pooled pattern;
- the apparent law requires excluding inconvenient skeletons;
- strong models are uniformly correct and there is no non-obvious phenomenon;
- a result can be summarized entirely by existing MindGames/OmniToM/EAST/SimpleToM
  findings.

No prompt repair after seeing the result.

---

## 14. What happens next

This design file is editable.

The next legitimate engineering steps are:
1. write a transparent material builder;
2. generate the 24 × 4 contexts;
3. manually audit them;
4. implement gold and tests;
5. implement the analyzer on dummy outputs;
6. freeze the exact three-model panel;
7. copy the final design into a dedicated preregistration;
8. create a freeze tag;
9. only then generate target outputs.

CK-P1 remains a discovery experiment, not the paper.

## 15. Pre-freeze material-length correction (2026-09-06)

A dry generation audit found that the first literal K2/K3 templates repeated the full
proposition at every embedded level. Before any target-model output, this produced a
needlessly large context-length gradient:

- CK: about 38–40 words;
- K1: about 39–44 words;
- K2: about 67–71 words;
- K3: about 94 words on average.

This was corrected **before freeze and before any target output** by replacing repeated
copies of P inside K2/K3 with ordinary anaphora such as "this fact" / "it", while
preserving the exact finite epistemic structure.

After the correction, the dry material audit is approximately:

- CK: 38–40 words;
- K1: 39–44 words;
- K2: 56–59 words;
- K3: 70–73 words.

No filler was added to force exact token equality. Exact token matching would make the
stories less natural and is not the research variable. Length remains recorded as a
possible descriptive nuisance; any apparent law that is fully predicted by story
length must be killed.

The correction also makes the design more faithful to the project's data rule:
**remove gratuitous complexity rather than balancing it with more artificial text.**
