# G30 local data-agent brief (before model inference)

Create a small, transparent **theory-anchor pilot** for evidence admissibility using a binary diagnostic signal. This is not a new natural-language benchmark and must never be described as independent confirmation of VitaminC. The motivating precedent is Gonçalves, Libgober, and Willis (2026), *Retractions: Updating from Complex Information*; do not copy their stimulus text.

Read only this brief and the files you create. Do not inspect model outputs or old item pools. Write `data/items/g30_bayesian_status_pilot_v1.jsonl` and `results/audits/g30_bayesian_status_pilot_audit.md`. The JSONL must have exactly 40 rows: prior P(Blue) in `{0.20,0.35,0.50,0.65,0.80}` × reliability in `{0.65,0.75,0.85,0.95}` × E2 report in `{Blue,Yellow}`. Use an exact deterministic loop, not ad hoc handpicked examples. Each row needs `id`, `prior_blue`, `reliability`, `e2_report`, `e1_report` (always opposite E2), `bayes_p_blue_after_e2`, and clear stimulus text for conditions D, N, I, R. For Bayesian update use equal sensitivity/specificity: P(report=Blue|state=Blue)=reliability and P(report=Blue|state=Yellow)=1-reliability. State all probabilities as percentages in prompts.

Task story: A sealed device is either Blue or Yellow. A diagnostic report matches the true state with the specified reliability; independent reports have independent errors. Before final judgment, report E1 is displayed; E2 follows. The final admissible information is only prior and E2. D shows only E2. N displays a **same-device, opposite-color E1** and marks it invalid from the moment of display. R first presents that same E1 as valid, then revokes it for a procedural random audit unrelated to the device state and report value. I displays an **otherwise identical opposite-color report about a separate unrelated device**, marked invalid from first display. N/I should have matched turn count, task instructions, and nearly matched wording. Random invalidation must not imply anything about the state or E2 reliability. State clearly that an invalid report supplies zero valid information. Each condition ends with the same E2 report and asks for one probability from 0 to 100 that the target device is Blue, plus a forced Blue/Yellow decision. Keep prompts plain and concise. Do not include the Bayes answer in the stimulus.

In the audit, check **all 40 rows** mechanically and item by item: exact factorial coverage and unique IDs; E1 always opposite E2; N/R/I have identical final admissible set; N/I differ in target relevance and no other intended factor; numeric Bayesian values independently recomputed; prompts contain no leaked answer; no accidental prior/reliability mismatch; instruction naturalness/clarity. Record any flaw and fix it before freezing. Include SHA-256 of final JSONL and a short caveat that the task is constructed and tests transfer of the behavioral distinction, not a natural evidence use case. Do not run model inference or edit other files.
